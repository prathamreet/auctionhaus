## Paper 1: The Shill-Bidding Detection Paper

### Metadata

```
Title:  Real-Time Shill-Bidding Detection via Online Bid-Graph 
        Analytics in Live Auction Platforms
Authors: Asha Joseph, Pratham Reet, Nitin A. Rane, Reeshav Sinha, Om Ji Rao
Venue:  IEEE conference format (IEEEtran document class)
Length: 8 sections, ~5 pages two-column
```

### Section I: Introduction

States the problem: shill bidding is illegal and harmful, but all prior detection work is post-hoc. This paper introduces a system that flags suspicious bids in real time, within milliseconds, while the auction is live.

Four claimed contributions:
1. Online detection engine (the FraudEngine)
2. Repeatable evaluation corpus (the simulator)
3. Sealed-bid privacy (the commit-reveal scheme)
4. Throughput benchmarks (the Redis Stream sequencer)

### Section II: Literature Survey

Three subsections:
- **Comprehensive surveys**: Phua et al. (2010) fraud detection survey, Akoglu et al. (2015) graph anomaly detection survey
- **Graph-based auction fraud**: NetProbe (Pandit et al. 2007), Ford et al. (2010), Tsang et al. (2014), Newman-Girvan modularity
- **Real-time detection**: Sadaoui & Wang (2017) — the only prior work with a real-time framing, which our system supersedes with a per-bid streaming approach

### Section III: Related Work

Deeper comparison with:
- Trevathan & Read (2007) — shill score from complete histories; requires auction to end first
- Ford et al. (2010) — bidder-seller co-occurrence graphs; rebuilt from scratch post-auction
- Tsang et al. (2014) — community detection; needs 3+ completed auctions
- Brandt (2006) — cryptographic auction protocols; context for our commitment scheme
- Kleppmann (2017) — event-sourcing; context for our Redis Stream approach

### Section IV: System Design

Platform architecture: Express + Socket.io + Prisma + BullMQ + Next.js + simulator package.

Three auction formats on one Auction model.

Financial integrity: NUMERIC(18,2), SELECT FOR UPDATE, wallet lock ordering.

### Section V: Fraud Detection Method

The core research content:

**Sliding-window bid graph G(t, W)**: W=30 minutes, O(1) amortised update, lazy pruning.

**Five features** (F1-F5): response time τ, bid frequency φ, increment ratio ρ, seller co-occurrence σ, reciprocity γ. Each formally defined.

**Classification**: z-score normalization + logistic regression with bias. Decision threshold θ=0.20 (paper-era value; updated to 0.5 after Phase RP-2 pipeline fix).

**Explainability**: natural-language reason string per flag.

### Section VI: Evaluation

**Setup**: 60-second English auction, starting ₹1,000, minimum increment ₹100. Six agents: 2 truthful, 1 sniper, 1 shill, 2 collusion. Labels: `isShill=true` for shill+collusion bids.

### Section VII: Security Analysis

**Commit-Reveal protocol**: hiding property (SHA-256 behaves as random oracle), binding property (collision resistance).

**Limitation**: server cannot verify amount ≥ reservePrice without seeing amount. Future work: Pedersen + Bulletproofs.

**Threats to validity**:
- Internal: clean synthetic data, small corpus (70 training examples)
- External: single machine, not distributed
- Construct: F1 at fixed threshold; precision-recall curve more meaningful in class-imbalanced production

### Section VIII: Conclusion

Summarises contributions. Future work:
1. Train on real labelled dataset
2. Pedersen commitments + Bulletproof range proofs
3. Online stochastic gradient descent
4. Distributed Redis Stream consumer group

## Paper 2: The Atomic Ladder Protocol Paper

### Metadata

```
Title:  Atomic Ladder Execution Protocol for Concurrent 
        Proxy Bidding in Online Auctions
Format: IEEE conference, 8 sections, ~6 pages
```

### The Problem Statement

Three ways to implement proxy bidding:
1. **Closed-form jump**: compute final price in one step, create one bid. Fast, but log-unfaithful.
2. **Recursive nested transactions**: call `placeBid` recursively. Fails under Prisma (no nested interactive transactions), deadlocks under load, not durable.
3. **Atomic ladder**: one transaction, per-increment logging, BullMQ durability.

### The Protocol Formal Specification

The paper defines five desired properties:

- **P1 (Log Fidelity)**: For any sequence of proxy bids, the system produces one bid record per price increment.
- **P2 (Atomicity)**: Either all bid records for a ladder are committed or none are.
- **P3 (Isolation)**: A concurrent manual bid during a ladder sees the auction's state after the ladder completes.
- **P4 (Deadlock Freedom)**: No transaction deadlock is possible under the two-tier lock ordering.
- **P5 (Bounded Execution)**: The ladder terminates in at most `(maxAmount - startPrice) / minIncrement + 2` iterations.

### Three Theorems with Proofs

**Theorem 1 (Log Fidelity)**: By induction. Each loop iteration creates exactly one Bid row at `currentPrice + minIncrement`. The loop terminates only when no auto-bid can reach the next price. QED.

**Theorem 2 (Vickrey Equivalence)**: The final price after the ladder is `P* = min(M₁, M₂ + δ)` where M₁ is the highest max, M₂ is the second highest, and δ is the minimum increment. This is the Vickrey equilibrium price for an English proxy auction — the winner pays the minimum amount needed to win, not their full max.

**Theorem 3 (Deadlock Freedom)**: By contradiction. Assume a cycle exists in the wait-for graph: T1 waits for T2, T2 waits for T1. This requires T1 holds a lock that T2 needs and vice versa. With the two-tier lock ordering (auction first, wallets ascending by userId), T1 and T2 acquire locks in the same order. They cannot hold each other's "first needed" lock — one would have to wait before acquiring anything. The cycle cannot form.

### Evaluation

Three implementations benchmarked under concurrent load:

| Implementation | Throughput (100 VUs) | Determinism | Log Fidelity |
|----------------|---------------------|-------------|--------------|
| Closed-form jump | highest | PASS | FAIL |
| Recursive nested tx | medium | FAIL | PASS |
| Atomic ladder | high | PASS | PASS |

Determinism is measured by SHA-256 hashing the complete bid log: if two runs with identical inputs produce the same hash, the implementation is deterministic.

The recursive nested transaction implementation FAILS determinism under load because the flattened inner transactions see each other's uncommitted state, producing non-deterministic orderings.

## The Patent Draft

`paper/patent-draft.md` is an Indian Form 2 provisional patent specification.

**Title:** "System and Method for Atomic Resolution of Concurrent Proxy Bids with Durable Per-Increment Logging in Online Auction Platforms"

**Claims:**

1. **Independent Claim 1** (broadest): A computer-implemented method for resolving concurrent proxy bids comprising: (a) receiving a trigger bid, (b) acquiring an exclusive database lock on the auction record, (c) loading all active proxy bid records ordered by maximum amount descending, (d) iteratively inserting bid records at each price increment, (e) atomically updating wallet escrow balances, (f) releasing the lock after a final commit.

2–8. **Dependent claims** narrow to:
- Specific database engine (PostgreSQL)
- Specific lock ordering (wallet IDs ascending)
- Idempotency under re-delivery (checking `status !== ACTIVE` under lock)
- Anti-sniping exemption (extension happens only on the triggering manual bid)
- Real-time event broadcast (Socket.io)
- System claim (the full apparatus)
- Computer-readable medium claim

**Filing notes:**
- Indian Provisional Patent costs ~₹1,600 government fee
- Priority date established upon filing; formal specification must follow within 12 months
- Non-obviousness argument: the specific combination of per-increment logging + atomic transaction + BullMQ durability + wallet lock ordering has not appeared in prior art (eBay's implementation is a black box; academic papers describe the desired outcome, not a specific implementation)
