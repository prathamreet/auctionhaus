\block{Problem}{
  Shill bidding inflates auction prices. Existing detectors operate
  \textbf{post-hoc} on completed logs. We need real-time detection to intervene
  \textbf{before} the auction closes.

\block{System Architecture}{
  \begin{itemize}
    \item Node.js (TypeScript) · Express · Socket.io · PostgreSQL · Redis
    \item BullMQ workers (auto-bid ladder, notifications)
    \item In-process fraud engine — no external ML service
    \item Next.js frontend with live admin fraud dashboard
  \end{itemize}
}

\column{0.34}

\block{5-Feature Bid Graph}{
  \begin{enumerate}
    \item \textbf{Response time} ($\tau$) — sub-500ms = bot
    \item \textbf{Bid frequency} ($\phi$) — bids/min in 30-min window
    \item \textbf{Increment ratio} ($\rho$) — scripted min-increment pattern
    \item \textbf{Seller co-occurrence} ($\sigma$) — same seller, many auctions
    \item \textbf{Reciprocity} ($\gamma$) — mutual outbidding = collusion ring
  \end{enumerate}

  Sliding window graph updated on each bid event ($<1$ms overhead).
  Features z-scored, scored by logistic regression:
  \[
    P(\text{shill}|\mathbf{z}) = \sigma(\beta_0 + \textstyle\sum_i \beta_i z_i)
  \]
}

\column{0.33}

\block{W1: Commit-Reveal Sealed Bids}{
  Client commits $H = \text{SHA-256}(\text{amountHex} \| \text{:} \| \text{nonce})$
  during live phase. Server stores hash only. Reveal after close.
  \begin{itemize}
    \item \textbf{Hiding}: server cannot learn amount during bidding
    \item \textbf{Binding}: bidder cannot change amount after committing
  \end{itemize}
}
