## Notes for Future Self

- `FraudEngine.onBid()` is fire-and-forget. It runs two extra DB reads (`auction` + `user`) after every bid. These are cheap (indexed by PK) but add ~2ms. Under extreme load, consider caching auction meta in the engine itself (LRU by auctionId, invalidate on `auction:ended`).
- The `BidSequencer.getActiveStreamKeys()` uses REDIS SCAN which is O(n keys in Redis). Fine for dev; in prod, maintain an explicit set of active auction IDs in a Redis SET and use `SMEMBERS` instead.
- `fraud.classifier.ts` `WEIGHTS` are in log-odds space, not probability space. Changing a weight from 2.8 to 5.0 does NOT double the fraud rate — it changes the log-odds. Always verify the change via `eval:fraud` output before committing.
- The paper's `\input{tables/metrics.tex}` only works after `npm run eval:fraud` is run. The paper will fail to compile until that file exists. Added placeholder `metrics.tex` would be better — TODO for Phase D.
